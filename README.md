# 校园网自动登录工具包 · 使用说明

## 最终方案(已实测通过)

广东电信校园宽带用的是电信 CCTP **加密**协议,无法用 curl 重放,所以最终方案是:

**开机脚本检测到离线时,拉起官方"广东校园"App 借它的自动登录功能登录,
登录成功后立即强杀 App 并清理最近任务卡片。之后转入常驻看门狗:
每 2 分钟 ping 一次,全天任何时刻掉线(且连着校园网)都会自动重登。**

- App 冷启动会自动登录(实测),脚本只在自动登录失效时才补模拟点击
- 看门狗是一个睡觉的 root shell(约 1~2MB 内存、零 CPU、每 2 分钟醒一次),不影响日常使用
- 不想要看门狗(只开机登录一次):把脚本顶部 `WATCHDOG=1` 改成 `0`
- 想恢复更快:把 `CHECK_INTERVAL=120` 改成 `60`

## 手机端文件

| 路径 | 作用 |
|---|---|
| `/data/adb/service.d/campus_boot.sh` | 开机自动登录 + 看门狗脚本(KSU 开机自动执行) |
| `/data/adb/service.d/campus_boot.log` | 每次运行的日志(排错看这里) |
| `/data/adb/service.d/campus_watchdog.pid` | 看门狗进程号(防止重复启动) |

电脑端 `campus_boot.sh` 是脚本的源文件,改完重新推送到上面路径即可。

## 脚本流程

1. 单实例检查(已有看门狗在跑就直接退出)
2. 开机阶段:离线才登录;WiFi 没就绪就短等 90 秒,等不到也**不退出**,交给看门狗
3. 登录:拉起 App → 自动登录(最多 45 秒)→ 失败补模拟点击 → 强杀 App → 清最近任务卡片
4. 进入看门狗循环:每 2 分钟巡检一次:
   - **锁屏/息屏 → 暂停一切检测**(系统休眠时进程被冻结,零唤醒零耗电)
   - **解锁 → 10 秒内立即检测**,掉线且在校园网段则自动重登
   - WiFi 没开 / 不在校园网段(家用 WiFi、流量)→ 静默待命
   - 探测绑定 wlan0 网卡:开着流量/代理上网不会被误判"在线"而漏掉认证

## 锁屏行为(已实测)

| 状态 | 行为 |
|---|---|
| 锁屏/息屏 | 日志记 `locked: pause checks`,不做任何网络检测;系统休眠时进程被冻结,零耗电 |
| 解锁 | 10 秒内日志记 `unlocked: immediate check`,立即检测并按需登录 |

## WiFi 开关场景(已实测)

| 场景 | 行为 |
|---|---|
| 开机时 WiFi 关着 | 脚本不退出,转入看门狗;之后打开 WiFi,最多 2 分钟内自动登录 |
| 用着用着关了再开 | 同上,看门狗一直守着;会话若仍有效则什么都不做 |
| 全程不开 WiFi(流量上网) | 看门狗静默,零动作 |

## 排错

- 看日志:`adb shell su -c "cat /data/adb/service.d/campus_boot.log"`
- 日志出现 `exit: already-online` = 开机时本来就在线,正常
- 日志出现 `fail: still-offline` = 检查 App 里账号密码/自动登录是否还有效
- 换了屏幕分辨率/换机:重新用"指针位置"测坐标,改脚本里的 `TAP_MAIN_*` / `TAP_LOGIN_*`
